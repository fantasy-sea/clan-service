# 家庭远程助手
# MVP 服务端架构设计

## 1. 技术栈

### Backend

- Spring Boot
- Java
- Spring Web
- Spring WebSocket
- Spring Validation
- Spring Data JPA
- MySQL 8.x
- Jackson
- Lombok（如果项目允许）
- Flyway（数据库迁移）

### 实时通信

```text
WebSocket
```

用于：

- 设备在线状态
- 远程协助请求
- Session 状态
- 控制命令
- WebRTC Signaling

### 实时视频

```text
WebRTC
```

服务器只负责：

```text
SDP Offer
SDP Answer
ICE Candidate
```

服务器默认不处理视频流。

### NAT 穿透

```text
STUN
TURN
```

STUN/TURN 独立于 Spring Boot Backend。

```text

          手机 A                         手机 B
      Controller                       Agent
           │                              │
           │────── WebSocket ────────────►│
           │                              │
           │◄───── WebSocket ─────────────│
           │                              │
           │                              │
```

```text

    ↓

    ↓

    ↓
帮助 WebRTC 建立连接
```

# 5. Device

设备不是 Controller，也不是 Agent。

设备只是：

```text
Device
```

建立 Session 后才获得角色。

```java
public enum RemoteRole {
    CONTROLLER,
    AGENT
}
```

例如：

```text
Session A

你的手机
    role = CONTROLLER

父母手机
    role = AGENT
```

未来控制权切换：

```text
你的手机
    role = AGENT

父母手机
    role = CONTROLLER
```

因此数据库不要在 `devices` 表中保存：

```text
role
```

角色属于：

```text
remote_sessions
```

# 8. pairing_codes

匹配码不是永久密码。

默认：

```text
6 位数字
5 分钟有效
成功后立即失效
```

数据库：

```sql
CREATE TABLE pairing_codes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    device_id VARCHAR(64) NOT NULL,

    code_hash VARCHAR(128) NOT NULL,

    expires_at DATETIME NOT NULL,

    used_at DATETIME NULL,

    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_pairing_device
        FOREIGN KEY (device_id)
        REFERENCES devices(id),

    INDEX idx_pairing_code_hash (code_hash),

    INDEX idx_pairing_device (device_id),

    INDEX idx_pairing_expires (expires_at)
);
```

注意：

不要保存：

```text
582941
```

这种明文匹配码。

保存：

```text
hash(582941)
```

# 9. device_bindings

表示：

> 两台设备已经成为可信的家庭设备。

```sql
CREATE TABLE device_bindings (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    device_a_id VARCHAR(64) NOT NULL,

    device_b_id VARCHAR(64) NOT NULL,

    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_binding_device_a
        FOREIGN KEY (device_a_id)
        REFERENCES devices(id),

    CONSTRAINT fk_binding_device_b
        FOREIGN KEY (device_b_id)
        REFERENCES devices(id),

    UNIQUE KEY uk_device_binding (
        device_a_id,
        device_b_id
    )
);
```

建议业务层对：

```text
A → B
B → A
```

进行规范化。

例如永远：

```text
device_a_id < device_b_id
```

这样避免出现：

```text
A B

B A
```

被数据库认为是两个 Binding。

# 10. remote_sessions

这是整个远程协助系统的核心表。

```sql
CREATE TABLE remote_sessions (
    id VARCHAR(64) PRIMARY KEY,

    status VARCHAR(32) NOT NULL,

    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    accepted_at DATETIME NULL,

    connected_at DATETIME NULL,

    ended_at DATETIME NULL,

    CONSTRAINT fk_session_controller
        FOREIGN KEY (controller_device_id)
        REFERENCES devices(id),

    CONSTRAINT fk_session_agent
        FOREIGN KEY (agent_device_id)
        REFERENCES devices(id),

    CONSTRAINT fk_session_control_device
        FOREIGN KEY (control_device_id)
        REFERENCES devices(id),

    INDEX idx_session_controller (
        controller_device_id
    ),

    INDEX idx_session_agent (
        agent_device_id
    ),

    INDEX idx_session_status (
        status
    )

```

# 19. 创建 RemoteSession

例如：

```text
你的手机
    ↓
请求控制
    ↓
爸爸手机
```

请求：

```http
POST /api/v1/sessions
Authorization: Bearer <deviceToken>
```

```json
{
  "targetDeviceId": "dev_parent_001"
}
```

服务器必须检查：

```text
1. 当前 Device 是否存在
2. Target Device 是否存在
3. 两台 Device 是否 Binding
4. Target 是否在线
5. 是否已有 ACTIVE Session
```

成功：

```json
{
  "code": 0,
  "data": {
    "sessionId": "session_001",
    "controllerDeviceId": "dev_me",
    "agentDeviceId": "dev_parent_001",
    "status": "REQUESTING"
  }
}
```

# 20. RemoteSession 建立后的角色

例如：

```text
controllerDeviceId
    = dev_me

agentDeviceId
    = dev_parent
```

同时：

```text
controlDeviceId
    = dev_me
```

代表：

```text
dev_me
    ↓
拥有控制权
```

---

# 21. 为什么需要 controlDeviceId

因为未来支持控制权切换。

开始：

```text
controller = A
agent = B

controlDevice = A
```

切换：

```text
controller = A
agent = B

controlDevice = B
```

甚至未来可以重新设计成：

```text
screenSourceDevice
controlDevice
```

两个独立维度。

这样可以支持：

```text
A 看 B
B 控制 A
```

这种更复杂的模式。

MVP 暂时保持：

```text
controller = controlDevice
agent = screenSourceDevice
```

# 22. Accept Session

父母手机收到：

```text
REMOTE_REQUEST
```

点击：

```text
允许
```

调用：

```http
POST /api/v1/sessions/{sessionId}/accept
Authorization: Bearer <deviceToken>
```

服务器必须验证：

```text
当前 Device == agentDeviceId
```

不能让第三方接受 Session。

状态：

```text
REQUESTING
      ↓
ACCEPTED
```

同时通过 WebSocket 通知 Controller：

```json
{
  "type": "SESSION_ACCEPTED",
  "sessionId": "session_001",
  "payload": {}
}
```

# 45. Session CONNECTED 的判断

不要仅仅因为：


```json
  "payload": {}
```


# 65. WebSocket 安全

服务器必须检查：

```text
AUTH
    ↓
Device Token
    ↓
Device
    ↓
WebSocketSession
```

以后每个消息：

```text

       ↓
当前 Device
       ↓
Session 权限
```

不能相信客户端发送的：

```json
{
  "fromDeviceId": "dev_xxx"
}
```

真正的 sender 必须来自：

```text
WebSocketSession
```

而不是 payload。

这是非常重要的安全规则。

# 66. CONTROL 安全检查

服务器收到：

```text

```

必须执行：

```text
WebSocketSession
       ↓
获取 senderDeviceId
       ↓
获取 session
       ↓
Session.status == CONNECTED
       ↓
sender 属于 Session
       ↓
sender == controlDeviceId
       ↓
target == agentDeviceId
       ↓
转发
```

任何一步失败：

```text
拒绝
```

# 67. Pairing Code 防暴力破解

6 位数字只有：

```text
1,000,000
```

种组合。

所以必须限流。

例如：

```text
同一 Device
    ↓
1 分钟最多 5 次验证

同一 IP
    ↓
1 分钟最多 N 次
```

连续失败可以增加冷却时间。

MVP 即使暂时不引入 Redis，也应该在 Service 中预留：

```text
PairingRateLimiter
```

接口。

以后再使用 Redis 实现。

# 73. MVP 核心原则

整个服务端必须始终遵守以下原则：

```text
1. Device ≠ User

2. Device ≠ Controller / Agent

3. Role 属于 RemoteSession

4. Pairing Code 只负责第一次建立关系

5. Binding 负责长期设备关系

6. Session 负责一次远程协助

7. WebSocket 负责实时控制和 Signaling

8. WebRTC 负责实时屏幕

9. Spring Boot 不接收屏幕视频

10. TURN 独立于业务服务器

11. CONTROL 必须经过 Session 权限验证

12. 客户端发送的 deviceId 不能作为身份依据

13. Device 身份必须来自 WebSocket Authentication

14. Android 权限必须由系统授权

15. Session 必须可以被参与设备主动结束
```
